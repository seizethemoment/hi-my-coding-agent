# 11. 第十步：打包成真正的 CLI

## 本步目标

把这套 agent 从“项目里跑的脚本”升级成“像工具一样启动的 CLI”。

## 本步交付

- `bin/coding-agent.ts`
- `README.md` 更新
- 启动命令约定

## 为什么这一步重要

前 9 步完成后，你已经有一个可工作的系统。

但如果没有标准 CLI 入口：

- 使用成本高
- 文档难写
- 后续扩展命令行参数也不方便

## 建议的 CLI 入口能力

至少支持：

- 默认进入交互态
- `--model`
- `--base-url`
- `--workdir`
- `--print-config`

注意：

命令行参数应该覆盖环境变量，但不要和配置层打架。

## 这一步先不要做什么

先不要做：

- 单文件二进制打包
- 自动升级器
- 复杂插件市场

目标只是让它像一个正常 CLI 一样工作。

## 本步验收标准

完成后至少要做到：

1. 有统一启动入口
2. 参数、环境变量、默认值关系清楚
3. 文档里可以用一条命令启动 agent

## 常见坑

### 1. CLI 参数直接散写在 `index.ts`

后面维护会很烦。

### 2. 参数覆盖规则不明确

模型配置最怕不透明。

### 3. README 还停留在开发者视角

到这一步，README 要能指导别人运行。

## 到这里为止，你已经完成了什么

完成第十步后，其实第一版基础 coding agent 已经成立了：

- 本地 CLI
- 模型调用
- 工具系统
- tool loop
- 会话日志
- 安全边界
- 上下文文件
- 测试

这已经不是 demo，而是一个基础可用的 agent harness。
