# 12. 第十一步：技能系统与 MCP 适配层

## 这一章的定位

这一步不是第一版闭环必需，但它决定了你的 agent 以后能不能优雅扩展。

## 本步目标

先做一个轻量、够用、可解释的扩展层。

不求一步到位实现完整 MCP 生态，先把下面两件事做好：

- 技能加载
- 外部工具接入接口

## 本步交付

- `src/skills/loader.ts`
- `skills/example/SKILL.md`
- `src/ext/toolProviders.ts`

## 什么是技能系统

技能系统本质上是：

- 一段可按需加载的说明
- 可能附带脚本、模板、资源
- 只有在任务需要时才注入上下文

这和“一上来把所有知识塞进 system prompt”完全不是一回事。

## 第一版技能系统建议做到什么程度

足够简单就好：

1. 扫描 `skills/` 目录
2. 根据名称找到 `SKILL.md`
3. 在用户请求显式提到时再加载
4. 把技能内容追加到上下文中

这已经足够模拟主流产品中的基础技能能力。

## 什么是 MCP 适配层

这一版不建议直接全量实现 MCP 协议。

更合理的做法是先抽象出：

- 外部工具提供者接口
- 工具清单发现
- 调用适配

这样以后要接：

- 真 MCP server
- 内部服务
- 浏览器工具

都还有空间。

## 本步验收标准

完成后至少能做到：

1. 用户提到某个技能时，agent 能加载对应 `SKILL.md`
2. agent 的工具层预留了接第三方工具的适配接口
3. 核心 loop 不需要为技能系统重写

## 常见坑

### 1. 把技能做成“永久注入上下文”

这会让上下文越来越脏。

### 2. 为了 MCP 直接引入大量复杂协议代码

你现在需要的是扩展点，不是协议论文。

### 3. 技能系统和工具系统混成一层

技能更像“知识 / 流程包”，工具更像“能力接口”。
